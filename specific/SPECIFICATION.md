# 数学ガール — インタラクティブ数学教育プラットフォーム 仕様書

## 1. プロダクトビジョン

### 1.1 核心思想

**「会話しながら書けるよね」**

ユーザーが数学ガールキャラクター（アリス）と対話しながら、数学のノートをリアルタイムで書き進めるアプリケーション。対話とノート記述が非同期かつ双方向に影響し合い、数式を書くとキャラが反応し、会話から数式がノートに追加される。

### 1.2 プラットフォーム戦略

```
Phase 1: Web（Next.js） ← 現在
Phase 2: Flutter（Web + モバイル + デスクトップ）
Phase 3: マルチプラットフォーム展開
```

### 1.3 現行システムからの進化

| 項目 | 現行（v1） | 次期（v2） |
|------|-----------|-----------|
| メイン機能 | 音声チャット + VRM表示 | 対話 + ノート + 数式 + 動画 |
| UI | チャット画面中心 | 4エリア分割レイアウト |
| 数式 | なし | MathLive / MathJSON |
| コンテンツ | リアルタイム会話のみ | セクション分割 + 動画生成 |
| 認証 | なし | Google ログイン |
| データ永続化 | PostgreSQL（会話ログ） | ユーザー / ダイアログ / テキスト / ノート |

### 2.2 表示トグル

- テキスト表示: ON / OFF

### 2.3 キャラクター演出

- **「キャラが書く」**: キャラクターが黒板的なものに数式を書く演出
- 動画は2〜3パターンの切替（待機 / 説明中 / 書き込み中 など）
- クラウド環境上で対話駆動により動画パターンを選択
- **既存の動画APIを利用**: 外部に動画生成・配信APIが存在し、動画UUID + 生成ID の2キー構造で動画を管理・取得する

### 2.4 黒板エリア（まとめ / 数式エリア）の詳細

キャラクター（アリス）の対話発話ごとに、数式部分を自動抽出し、黒板風のエリアにリアルタイムで表示する。

**動作フロー:**

```
アリスの応答テキスト
  │
  ▼
数式抽出エンジン（LLM or 正規表現）
  │  対話テキストから LaTeX / MathJSON の数式部分を識別
  │
  ▼
黒板エリアに数式を追加表示
  │  - 新しい数式が出るたびに黒板に「書き足す」演出
  │  - キャラが書いている感じのアニメーション連動
  │  - 過去の数式は残り、セッション中の数式が蓄積
  │
  ▼
ユーザーは黒板の数式をノートにコピー可能
```

**数式抽出の方針:**
- 対話応答に含まれる `$...$` や `$$...$$` 形式の数式を検出
- LLM にプロンプトで「数式部分のみ抽出」を依頼する方式も併用可能
- 抽出された数式は MathJSON 形式でも保持し、黒板 → ノートへの転記をサポート

### 2.5 ノートエリアの詳細 — ユーザーが書き込む場所

ノートは**ユーザーが主体的に書く場所**。キャラクターやAIはあくまで補完・検証の役割にとどまり、ノートの主権はユーザーにある。

Markdown + MathLive + AI補完を統合した**自作エディタ**で、数式を簡単に書ける環境を提供する。

**将来的には差分（diff）ベースの書き込み管理**を導入し、ノートの変更履歴を追跡・復元可能にする。

**エディタ構造:**

```
┌─────────────────────────────────────────────────────────┐
│  ノートエディタ（Markdown + MathLive + AI補完）            │
│                                                          │
│  ## オイラー＝ラグランジュ方程式          ← Markdown 見出し │
│                                                          │
│  ハミルトニアンを用いた導出              ← Markdown テキスト│
│                                                          │
│  ┌─────────────────────────────────┐                     │
│  │  d/dt(∂H/∂q̇) − ∂H/∂q = 0      │  ← MathLive 数式   │
│  └─────────────────────────────────┘                     │
│                                                          │
│  ┌─────────────────────────────────┐                     │
│  │  q̈ = −∂V/∂q                    │  ← MathLive 数式   │
│  │           ✅ 計算正解（自動検証）  │                     │
│  └─────────────────────────────────┘                     │
│                                                          │
│  ┌─ AI補完 ─────────────────────────┐                    │
│  │  💡 次の式: ∂²V/∂q² = ...       │  ← Tab で挿入      │
│  └──────────────────────────────────┘                    │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

**AI補完の動作:**

| 補完タイプ | トリガー | 例 |
|-----------|---------|-----|
| 数式補完 | MathLive 入力中に一時停止 | `∂H/∂` → `∂H/∂q` を提案 |
| 次の式提案 | 数式ブロック完了後 | 前の式から導出される次のステップ |
| Markdown 補完 | テキスト入力中 | セクション見出しや説明文の候補 |
| テンプレート | 空のブロックで起動 | 証明テンプレート、定理形式 など |

**キャラクター × MathLive 自動計算連携:**

```
ユーザーがノートに数式を入力
  │
  ▼
MathLive が MathJSON として解析
  │
  ├──► MathLive の Compute Engine で自動計算
  │       │
  │       ├──► 計算結果の正誤判定
  │       ├──► 式の簡約・展開
  │       └──► 導関数・積分の自動計算
  │
  ▼
キャラクター（アリス）がリアクション生成
  │
  ├──► 正解の場合:「すごい！合ってるよ！」+ 次のステップを提案
  ├──► 不正解の場合:「ここ、もう一回見てみよう？」+ ヒントを提示
  └──► 途中式の場合:「ここから先を一緒にやってみよう」+ 続きを黒板に表示
```

**MathLive Compute Engine の活用例:**

| 機能 | 説明 | キャラクターの振る舞い |
|------|------|----------------------|
| 式の評価 (evaluate) | 数式の数値計算 | 計算結果を確認し正誤をフィードバック |
| 式の簡約 (simplify) | 式の簡約化 | 「これ、もっとシンプルにできるよ」 |
| 式の展開 (expand) | 式の展開 | 「展開してみるとこうなるね」と黒板に書く |
| 導関数 (diff) | 微分の計算 | 「微分すると…」とステップを示す |
| 等価判定 (isEqual) | 2つの式が等しいか | ユーザーの回答が正解と等価かを判定 |

**データ保存形式（現行: スナップショット）:**

ノートは以下のブロック構造で保存:

```json
{
  "note_id": "uuid",
  "version": 1,
  "blocks": [
    {
      "block_id": "b1",
      "type": "markdown",
      "content": "## オイラー＝ラグランジュ方程式"
    },
    {
      "block_id": "b2",
      "type": "mathlive",
      "latex": "\\frac{d}{dt}\\frac{\\partial H}{\\partial \\dot{q}} - \\frac{\\partial H}{\\partial q} = 0",
      "mathjson": ["Subtract", ["Derivative", ...], ...],
      "validation": {
        "is_correct": true,
        "checked_at": "2026-02-10T12:00:00Z"
      }
    }
  ]
}
```

**将来: 差分（diff）ベースの書き込み管理**

ノートの編集を差分として記録し、変更履歴の追跡・任意バージョンへの復元を可能にする。

```
ノートの状態遷移（差分チェーン）:

  v1（初期）        v2（+数式追加）      v3（+修正）
  ┌─────────┐     ┌─────────┐         ┌─────────┐
  │ block b1 │ ──► │ diff: +b2│ ──────► │ diff: ~b2│
  │ (見出し)  │     │ (数式追加)│         │ (数式修正)│
  └─────────┘     └─────────┘         └─────────┘
```

差分レコードの構造:

```json
{
  "diff_id": "uuid",
  "note_id": "uuid",
  "version": 3,
  "parent_version": 2,
  "timestamp": "2026-02-10T12:05:00Z",
  "operations": [
    {
      "op": "update",
      "block_id": "b2",
      "field": "latex",
      "old": "\\dot{q} = ...",
      "new": "\\ddot{q} = -\\frac{\\partial V}{\\partial q}"
    }
  ]
}
```

差分管理により実現できること:

| 機能 | 説明 |
|------|------|
| 変更履歴 | いつ・何を書き変えたかを時系列で確認 |
| バージョン復元 | 任意の時点のノート状態に戻れる |
| 学習過程の可視化 | 思考の変遷を振り返り可能 |
| キャラとの連携 | 「さっき直した式、元はこうだったよね」とキャラが参照 |
| 差分ベースの同期 | 全体再送信でなく差分のみ送信で効率的に同期 |
```

### 2.6 対話ログエリアの詳細 — ノートとの分離 + クイズ機能

対話ログはノートとは**完全に分離**された独立エリア。ノートは「自分の学習記録」、対話ログは「キャラクターとのやりとり」として役割を明確に分ける。

**分離の原則:**

```
┌─────────────────────┐    ┌─────────────────────┐
│   ノートエリア        │    │   対話ログエリア      │
│   （ユーザーの領域）   │    │   （キャラの領域）    │
├─────────────────────┤    ├─────────────────────┤
│ - 自分で書く数式     │    │ - キャラとの会話履歴  │
│ - 自分の理解メモ     │    │ - キャラからのクイズ   │
│ - Markdown + MathLive│    │ - 正解/不正解の記録  │
│ - 永続保存される     │    │ - ライブトランスクリプト│
│                     │◄──►│                     │
│ 黒板の数式をコピー可 │    │ クイズ回答→ノートに記録│
└─────────────────────┘    └─────────────────────┘
         ↑↓ 独立して操作可能（非同期）  ↑↓
```

**クイズ機能:**

キャラクター（アリス）が対話の流れの中で自然にクイズを出題する。

```
対話ログでのクイズ表示例:

  アリス: 「じゃあ、ここで問題！」
  ┌─────────────────────────────────┐
  │  🧮 クイズ                       │
  │                                  │
  │  f(x) = x³ + 2x を微分すると？   │
  │                                  │
  │  ┌────────────────────────────┐  │
  │  │  MathLive 回答入力欄        │  │
  │  │  f'(x) = ___               │  │
  │  └────────────────────────────┘  │
  │                                  │
  │  [回答する]                      │
  └─────────────────────────────────┘

  → ユーザーが回答
  → MathLive Compute Engine で正誤判定
  → アリス:「正解！ 3x² + 2 だね！」or「惜しい！もう一回やってみよう」
```

**クイズ出題のトリガー:**

| トリガー | 説明 |
|---------|------|
| セクション区切り | 新しいセクションに進む前の理解度確認 |
| 数式入力後 | ユーザーが数式を書いた後、関連する応用問題 |
| 一定時間経過 | 対話が続いた後、学習定着のための確認 |
| ユーザー要求 | 「問題出して」と言われた場合 |

**クイズのデータ構造:**

```json
{
  "quiz_id": "uuid",
  "session_id": "uuid",
  "question_latex": "f'(x) = ?  \\text{ where } f(x) = x^3 + 2x",
  "correct_answer_mathjson": ["Add", ["Multiply", 3, ["Power", "x", 2]], 2],
  "user_answer_mathjson": null,
  "is_correct": null,
  "hint_given": false,
  "created_at": "2026-02-10T12:00:00Z"
}
```

### 2.7 コンテンツ領域の詳細 — メタ思考の基盤 + インタラクティブコンポーネント

コンテンツ領域は**こちらが用意した話題**を格納するエリア。AIエージェントはこの話題を単に読み上げるのではなく、**メタ的に**（なぜこの話題か、何が本質か、どう繋がるか）考えた上で会話を組み立てる。

**メタ思考の構造:**

各コンテンツには教材本文に加えて、AIエージェント向けの**メタ情報**を付与する。

```yaml
# コンテンツのメタ情報（AI向け、ユーザーには非表示）
meta:
  topic: "微分の定義"
  goal: "極限の概念を直感的に理解させる"
  why: "微分は解析学の基礎であり、ここが曖昧だと後の応用で躓く"
  connections:
    - "積分（逆操作として後で扱う）"
    - "テイラー展開（近似の基礎）"
    - "物理の速度・加速度"
  common_mistakes:
    - "lim と 代入を混同する"
    - "dx を単なる記号と思って分数操作してしまう"
  depth_levels:
    basic: "直感的な説明（傾きとして）"
    intermediate: "ε-δ 論法の導入"
    advanced: "多変数への拡張"
  prerequisites:
    - "関数の極限"
    - "連続性"
```

メタ情報は**コンテンツ作成時に事前計算**しておく（リアルタイムでAIに解析させるとレイテンシが大きいため）。対話時は事前計算済みのメタ情報をプロンプトに注入するだけで済む。

AIエージェントはこのメタ情報を使って:

| メタ情報 | AIの活用方法 |
|---------|------------|
| goal | 会話全体の方向性を決める。ゴールに向かって話題を誘導 |
| why | 「なぜこれを学ぶのか」をユーザーに自然に伝える |
| connections | 他の話題との関連を会話の中で自然に言及 |
| common_mistakes | ユーザーが間違えそうなポイントを先回りしてフォロー |
| depth_levels | ユーザーの理解度に応じて説明の深さを動的に変更 |
| prerequisites | 前提知識が怪しい場合、遡って説明 |

静的テキストだけでなく**インタラクティブコンポーネント**も埋め込める。

**コンポーネント一覧:**

| コンポーネント | 説明 | 使用例 |
|--------------|------|--------|
| グラフ描画 | 関数のプロット、パラメータ変更可能 | `y = ax² + bx + c` のグラフをスライダーで操作 |
| スライダー | 数値パラメータをリアルタイム変更 | 係数 a を動かして曲線の変化を観察 |
| シミュレーション | 物理・数学の動的シミュレーション | 振り子の運動、ベクトル場の可視化 |
| ステップ実行 | 証明や計算の段階的表示 | 「次のステップ」ボタンで式変形を順に追う |
| 穴埋め問題 | 式中の一部を空欄にした問題 | `d/dx(x³) = ___` に回答 |
| MathLive 埋込 | コンテンツ内に数式入力欄を配置 | 教材の演習部分で直接数式を入力 |

**コンテンツ記述形式:**

Markdown 内にカスタムブロックとしてコンポーネントを記述:

````markdown
# 二次関数のグラフ

二次関数 $f(x) = ax^2 + bx + c$ のグラフを見てみよう。

```interactive:graph
{
  "type": "graph",
  "function": "a * x^2 + b * x + c",
  "params": {
    "a": { "min": -5, "max": 5, "default": 1, "step": 0.1 },
    "b": { "min": -5, "max": 5, "default": 0, "step": 0.1 },
    "c": { "min": -5, "max": 5, "default": 0, "step": 0.1 }
  },
  "range": { "x": [-10, 10], "y": [-10, 10] }
}
```

スライダーを動かして、各係数がグラフにどう影響するか確認しよう。

```interactive:step
{
  "type": "step_execution",
  "steps": [
    { "label": "与式", "latex": "f(x) = x^3 + 3x^2 + 3x + 1" },
    { "label": "因数分解", "latex": "f(x) = (x + 1)^3" },
    { "label": "微分", "latex": "f'(x) = 3(x + 1)^2" }
  ]
}
```
````

**コンテンツ追加フロー:**

```
コンテンツ作成者 or AI が .md を生成
  │
  ▼
.md 内のインタラクティブブロックを解析
  │
  ▼
フロントエンドがコンポーネントを動的レンダリング
  │
  ├──► グラフ → Plotly / D3.js / Desmos API 等
  ├──► スライダー → React コンポーネント
  ├──► シミュレーション → Canvas / Three.js
  ├──► ステップ実行 → 状態管理付きコンポーネント
  └──► MathLive 埋込 → MathLive Web Component
```

### 2.8 キーアイデア — 4エリア間の双方向連携

ノートへの書き込みと対話が双方向に影響し合う。数式を書くとキャラが反応し、会話から数式が黒板に反映される。

```
┌──────────────┐         ┌──────────────┐
│  動画エリア    │◄───────►│  黒板エリア    │
│  (キャラクター)│  キャラが │ (数式表示)    │
│              │  書く演出 │              │
└──────┬───────┘         └──────┬───────┘
       │                        │
       │ 対話から数式抽出         │ 黒板の式をコピー
       │ → 黒板に反映            │ → ノートに転記
       │                        │
       ▼                        ▼
┌──────────────┐         ┌──────────────┐
│  対話ログ     │◄───────►│  ノートエリア  │
│ (会話+クイズ) │ 数式入力で│ (Markdown    │
│              │ キャラ反応│  +MathLive)  │
└──────┬───────┘         └──────┬───────┘
       │                        │
       │  クイズ出題              │  ノート記述が
       │  ↕                     │  コンテンツと連動
       ▼                        ▼
┌─────────────────────────────────────┐
│  コンテンツ領域                       │
│  (Markdown + インタラクティブ)        │
│  教材 → 対話のトピック → ノートに記録  │
└─────────────────────────────────────┘
```

**連携パターン:**

| 起点 | 行先 | 連携内容 |
|------|------|---------|
| ノート → 対話 | 数式を書く → キャラがリアクション |
| 対話 → 黒板 | 会話中の数式 → 黒板に自動表示 |
| 黒板 → ノート | 黒板の数式をワンクリックでノートに転記 |
| コンテンツ → 対話 | 教材のトピックがキャラの話題に |
| 対話 → ノート | クイズの回答結果をノートに記録 |
| コンテンツ → ノート | インタラクティブ操作の結果をノートに貼付 |

### 3.2 非同期設計の原則

本システムの中核となる設計原則:

1. **数式を書く間もキャラクターとの対話が可能** — ノート操作が対話をブロックしない
2. **ノートと会話は非同期** — ノートの編集と対話は独立したストリームとして並行進行
3. **ノートを書いている間にセクションが伸びていく** — セクションが動的に成長

ユーザーは MathLive で数式を記述しながら、同時にキャラクターと音声やテキストで会話を続けることができる。2つのストリームは互いを待たない。

```
時間軸 →

ユーザー:  [数式記述中]─────────────────[数式完了]──[次の数式]──────►
           ↕ 同時に対話可能             ↕          ↕
アリス:    [応答]──[補足説明]──[クイズ出題]──[正誤判定]──[次の話題]──►
ノート:    ──[数式追加]──────────[AI補完提案]──[セクション成長]────────►
黒板:      ──────[対話の数式を表示]──────────[更新]────────────────────►

（すべてが非同期・独立して進行。どの操作も他を待たない）
```

**技術的な実現:**

```
┌──────────────────┐     ┌──────────────────┐
│  会話ストリーム    │     │  ノートストリーム  │
│  (WebSocket)     │     │  (WebSocket)     │
│                  │     │                  │
│  ユーザー発話 ──► │     │  数式入力 ──────► │
│  ◄── AI応答      │     │  ◄── AI補完      │
│  ユーザー発話 ──► │     │  テキスト入力 ──► │
│  ◄── AI応答      │     │  ◄── セクション追加│
│       ...        │     │       ...        │
└────────┬─────────┘     └────────┬─────────┘
         │  独立した WebSocket      │
         │  接続で並行稼働           │
         └────── 双方向連携 ───────┘
         （数式を書く → キャラが反応）
         （会話で出た式 → 黒板に反映）
```

### 3.3 AIエージェント — 「知っている前提」の寄り添い型

AIエージェント（アリス）は、学習者がテキストの内容を**すでに知っている前提**で会話する。一方的に教えるのではなく、学習者の**理解を促進させる存在**。困っているときや質問してきたときにヒントを与え、自力での気づきを引き出す。

**アリスの立ち位置:**

```
                ×  教師型（上から教える、答えを与える）
アリスの役割 →  ○  理解促進型（問いかけ、気づきを引き出す）

  教師型:    「微分の定義はこうだよ。覚えてね」
  理解促進型: 「この式、展開してみるとどうなると思う？」
              「あ、そこ詰まった？ヒント出そうか？」
              「なんでこうなるか、自分の言葉で説明できる？」
```

**基本原則:**
1. テキストの内容について相手は知っている前提で話す
2. 自分から全部説明しない。質問や困りごとに応じてヒントを段階的に出す
3. ユーザーが自力で考える余地を残す — 答えではなく「気づき」を与える
4. 理解を深める問いかけをする（「なぜ？」「他にどんな場合がある？」「もし〜だったら？」）

**セッション開始時のフロー:**

```
セッション開始
  │
  ▼
テキスト入力（セッション中に変わらない固定コンテンツ）
  │
  ▼
メタ情報を生成（セッション開始時に1回だけ）
  ├── テキストの構造解析
  ├── つまずきやすいポイントの抽出
  ├── ヒントの候補生成
  └── セクション分割・要約
  │
  ▼
メタ情報生成完了 → 会話開始可能
  │
  ▼
対話（メタ情報を system プロンプトに注入済み。以降追加のメタ解析は不要）
```

**会話の流れ（具体例）:**

```
テキスト（固定）                AIエージェント                   ユーザー
  │                              │                             │
  │ 「微分の定義と応用」         │                             │
  ├── メタ情報生成 ────────────►│                             │
  │                              │  「今日のテーマは微分だね。   │
  │                              │   何か気になるところある？」  │
  │                              ├───────────────────────────►│
  │                              │                             │ 「特にないかな」
  │                              │◄────────────────────────────┤
  │                              │  「じゃあノートに              │
  │                              │   書き進めてみて！」          │
  │                              ├───────────────────────────►│
  │                              │                             │ （ノートに数式を記入）
  │                              │                             │ （途中で手が止まる）
  │                              │                             │
  │                              │  「ん、詰まった？              │
  │ メタ: common_mistakes 参照  │   ここ lim の扱いが          │
  ├─────────────────────────────►│   ポイントだよ」             │
  │                              ├───────────────────────────►│
  │                              │                             │ 「あ、そういうことか」
  │                              │◄────────────────────────────┤
  │                              │  「そうそう！いい感じ！」      │
  │                              ├───────────────────────────►│
  │                              │                             │ 「ε-δ がよくわからない」
  │                              │◄────────────────────────────┤
  │ メタ: depth_levels 参照     │  「じゃあ図で考えてみよう。   │
  ├─────────────────────────────►│   ε をこのくらい取ると…」   │
  │                              ├───────────────────────────►│
```

**メタ情報生成のタイミング:**

| タイミング | 処理 | レイテンシ |
|-----------|------|----------|
| セッション開始時 | テキストを解析しメタ情報を生成（1回だけ） | 数秒（会話開始前に完了） |
| 対話中 | 事前生成済みメタ情報を参照するだけ | ゼロ（注入済み） |
| ノート更新時 | ノート状態のみ軽量に取得 | 最小限 |

```
セッション開始時に1回:

  テキスト（固定）
    │
    ▼
  LLM でメタ情報を生成
    ├── goal: このテキストのゴール
    ├── key_points: 押さえるべきポイント
    ├── common_mistakes: つまずきやすい箇所
    ├── hints: ヒントの候補（段階的）
    ├── connections: 関連する話題
    └── depth_levels: 深掘り用の説明
    │
    ▼
  system プロンプトに注入 → 以降の対話はこれをベースに即応答
```

**プロンプト設計の方針:**

| 要素 | 注入方法 | タイミング |
|------|---------|----------|
| テキスト（固定） | system プロンプトにテキスト全文を埋め込み | セッション開始時 |
| メタ情報 | goal / hints / common_mistakes 等を注入 | セッション開始時に1回生成 → 注入 |
| キャラ設定 | 「知っている前提で話す」「ヒントは段階的に」等 | 静的 |
| 対話履歴 | dialog_messages を渡す | リアルタイム（自動） |
| ノート状態 | ユーザーのノート内容を要約して注入 | リアルタイム（軽量） |
| クイズ履歴 | 正解率・誤答パターンを注入 | リアルタイム（軽量） |

**[Future Work] バックグラウンド会話分析 — 能動的な問いかけ:**

将来的には、AIエージェントがユーザーの会話をバックグラウンドで定期的に分析し、「今何に困っているか」を推定して能動的に問いかけるようにする。

```
対話ストリーム（フォアグラウンド）        分析ストリーム（バックグラウンド）
  │                                      │
  │  ユーザー ↔ アリス 通常会話           │  一定時間ごとに起動
  │                                      │  （例: 30秒〜1分間隔）
  │                                      │
  │                                      ├── 直近の対話履歴を取得
  │                                      ├── ノートの状態を取得
  │                                      ├── LLM で分析:
  │                                      │     「ユーザーは今何に困っている？」
  │                                      │     「理解が止まっている箇所は？」
  │                                      │     「誤解していそうな概念は？」
  │                                      │
  │                                      ├── 分析結果:
  │                                      │     困りポイント推定
  │                                      │     ↓
  │  ◄──────────────────────────────────── │  アリスの次の発話に反映
  │  アリス:「さっきの式、                  │
  │   もしかして○○と△△を                   │
  │   混同してない？」                      │
  │                                      │
```

**分析の特徴:**
- ユーザーが明示的に「わからない」と言わなくても、会話の流れから困りポイントを推定
- 一定間隔でバックグラウンド実行するため、対話のレイテンシに影響しない
- 分析結果はアリスの次の発話タイミングで自然に織り込む（唐突にならないように）
- 「考えさせる」問いかけとして出す（答えを教えるのではなく、気づきを促す）

**[Future Work] 究極目標 — コンテンツ型学習からアハ体験型学習へ:**

最終的なビジョンは、用意されたコンテンツをなぞる学習から、**その場で生徒が困っていることをリアルタイムに解決する学習**への進化。

```
進化の段階:

  現在                     将来
  ┌─────────────┐         ┌─────────────────────────────┐
  │ コンテンツ型  │         │ アハ体験型                    │
  │             │         │                              │
  │ テキストに   │  ───►   │ 生徒の「今の困り」を起点に     │
  │ 沿って学ぶ   │         │ 対話しながら解決に導く         │
  │             │         │                              │
  │ テキスト→理解 │         │ 困り→対話→気づき→「あ！」     │
  └─────────────┘         └─────────────────────────────┘
```

**アハ体験を生む対話設計:**

```
生徒の状態                     アリスのアプローチ
  │                              │
  │ 「何がわからないかわからない」  │
  │ ─────────────────────────► │  困りの言語化を手伝う
  │                              │  「どこまではわかる？」
  │                              │  「この式のどこで引っかかった？」
  │                              │
  │ 困りが明確になる               │
  │ ◄───────────────────────── │
  │                              │
  │ 「○○がわからない」             │
  │ ─────────────────────────► │  困りを分解する
  │                              │  「○○って、AとBに分けると
  │                              │   どっちが難しい？」
  │                              │
  │ 核心にたどり着く               │
  │ ◄───────────────────────── │
  │                              │
  │ 「Aのところが…」              │
  │ ─────────────────────────► │  気づきを引き出す問いかけ
  │                              │  「じゃあ、もしxが0だったら
  │                              │   この式はどうなる？」
  │                              │
  │ 「あ！そういうことか！」       │
  │  ^^^ アハ体験 ^^^            │  「そう！そういうこと！」
  │                              │
```

**実現のための3ステップ:**

| ステップ | アリスの役割 | 目的 |
|---------|------------|------|
| 1. 困りの発見 | バックグラウンド分析 + 問いかけ | 生徒自身が「何がわからないか」を言語化できるようにする |
| 2. 困りの分解 | 段階的なヒントと質問 | 大きな「わからない」を小さな問いに分解する |
| 3. 気づきの誘発 | 具体例・反例・極端な場合の提示 | 自力で「あ！」と理解できる瞬間を作る |
| 4. 次の行動の明確化 | アハ体験を踏まえた具体的なネクストステップ提示 | 気づきを定着させ、学習の次の一歩を示す |

**アハ → 次の行動:**

アハ体験で終わらせない。気づいた瞬間に「じゃあ次はこれをやってみよう」と具体的な行動を提示し、学習を前に進める。

```
  「あ！そういうことか！」（アハ体験）
    │
    ▼
  アリス:「いいね！わかったんだね。
    じゃあ、今の理解を使って…」
    │
    ├──► 「この問題を解いてみよう」（演習の提示）
    ├──► 「ノートに自分の言葉でまとめてみて」（言語化の促進）
    ├──► 「次は○○に進んでみよう。今の話と繋がるよ」（次のトピックへ誘導）
    └──► 「さっき困ってた△△、もう一回やってみる？」（再挑戦の提案）
```

## 4. データベース設計

### 4.1 セッションの定義

**1対話 = 1セッション**。ユーザーが対話を開始してから終了ボタンを押すまでが1つのセッション。

```
セッションのライフサイクル:

  ページアクセス or 「新しい対話」
    │
    ▼
  セッション開始（session_id 発行、status = active）
    │
    ├── 対話（メッセージが dialog_messages に逐次追加）
    ├── ノート記述（notes に逐次保存）
    ├── テキスト閲覧（texts に記録）
    │
    ▼
  [終了ボタン] を押す
    │
    ▼
  セッション終了（status = completed、ended_at 記録）
    │
    ▼
  対話記録ページ（/history）から閲覧可能
```

- 終了ボタンを押さずにページを離れた場合 → セッションは `active` のまま残り、再開可能
- 対話中の各メッセージ（ユーザー/アリス）は `dialog_messages` にリアルタイムで保存
- セッション終了時にまとめてではなく、**対話中に逐次保存**する

## 5. 認証・アカウント

### 5.1 方針

初期段階では認証は不要。将来的に Google ログインを追加する。

- **実装場所**: フロントエンド側で対応
- **バックエンド**: 環境変数（Environment）に認証情報があれば OK とする設計
- バックエンドは認証トークンの検証のみ行い、OAuth フロー自体はフロント側で完結

### 5.2 将来の認証フロー（Google OAuth）

```
フロントエンド                        バックエンド
  │                                    │
  ├── Google OAuth 2.0 ログイン画面     │
  ├── Google からトークン取得           │
  ├── POST /api/auth/google ─────────► │ トークン検証
  │◄─────────────── JWT 発行 ──────────┤
  ├── 以降 JWT を Authorization に付与  │
  │                                    │
```

### 5.3 段階的導入

| フェーズ | 認証方式 | 説明 |
|---------|---------|------|
| v1（初期） | なし | ローカル/デモ利用。認証なしで全機能利用可能 |
| v2（将来） | Google OAuth | フロントで OAuth → バックに JWT → ユーザーデータ永続化 |

## 6. コンテンツパイプライン

### 6.1 OCR → テキスト化 → セクション分割 → 動画生成

手書きノートの写真から、既存の動画生成APIを使ってアニメーションを自動生成するパイプライン。

```
┌──────────────────┐
│ 手書きノート       │
│ （写真撮影）       │
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│   OCR処理         │    バックエンド側で処理
│   テキスト化       │    （ノートで何書いたかわかるように）
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│  textDB に格納     │    texts テーブルに保存
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│ セクション分割     │    section1, section2, section3...
│ （LLM で自動分割） │    各セクションの数式・テーマを識別
└──────┬───────────┘
       │  セクションごとに
       ▼
┌──────────────────────────────────────────────────┐
│  既存 動画生成API                                  │
│                                                   │
│  POST /api/job/animation/full                     │
│    content: セクションのテキスト                     │
│    ↓                                              │
│  generation_id 発行（セッションID）                  │
│    ↓                                              │
│  GET /api/job/{job_id}/status でポーリング          │
│  or /api/job/{job_id}/stream で SSE               │
│    ↓                                              │
│  完了 → video_id 取得                              │
│    ↓                                              │
│  GET /api/animation/{video_id} で動画取得          │
└──────────────────────────────────────────────────┘
```

### 6.2 既存動画生成API リファレンス

本システムは外部の動画生成APIを利用する。キー構造は **generation_id**（セッション）と **video_id**（動画）の2つ。

**主要エンドポイント:**

| エンドポイント | メソッド | 説明 |
|---------------|---------|------|
| `/api/job/animation/full` | POST | フル生成ジョブ（計画 + 生成）。content をテキストで渡す |
| `/api/job/animation/edit` | POST | 既存動画の編集ジョブ |
| `/api/job/animation/edit/stream` | POST | 編集ジョブを SSE ストリーミングで実行 |
| `/api/job/{job_id}/status` | GET | ジョブ状態取得（pending/running/completed/failed） |
| `/api/job/{job_id}/stream` | GET | 既存ジョブの SSE ストリーミング |
| `/api/animation/{video_id}` | GET | 生成済み動画ファイル（mp4）取得 |
| `/api/animation/get_info/{video_id}` | GET | 動画メタ情報取得 |
| `/api/generation/{generation_id}` | GET | セッション情報（動画リスト + 最新 video_id） |
| `/api/generation/{generation_id}/prompts` | GET | プロンプト履歴 |
| `/api/plan_animation` | POST | 計画立案のみ（generation_id 発行） |
| `/api/full_generation_animation` | POST | フルパイプライン（同期） |
| `/api/search_animation` | POST | RAG で類似動画検索 |
| `/api/register_rag/{video_id}` | POST | RAG 用に動画を登録 |

**データモデル:**

```
Generation Session （generation_id: int）
  │
  ├── Video 1 (video_id: string, edit_count: 0) ← 初回生成
  ├── Video 2 (video_id: string, edit_count: 1) ← 1回目の編集
  └── Video 3 (video_id: string, edit_count: 2) ← 2回目の編集
       └── latest_video_id = Video 3
```

**ジョブのライフサイクル:**

```
pending → running → completed（result に video_id 等）
                  → failed（error にメッセージ）

ステップ: initializing → planning → generating_script
        → linting → security_check → preflight
        → executing → refining → finalizing
```

### 6.3 OCR → 動画生成 の具体的なフロー

```
1. ユーザーが手書きノートの写真を撮影・アップロード
       │
       ▼
2. バックエンド: OCR でテキスト化
       │
       ▼
3. LLM でセクション分割
   入力: OCR テキスト全体
   出力: [
     { section: 1, title: "オイラー方程式の導出", text: "..." },
     { section: 2, title: "具体例", text: "..." },
     ...
   ]
       │
       ▼
4. セクションごとに動画生成ジョブを投入
   各セクションに対して:
     POST /api/job/animation/full
       content: セクションのテキスト
       │
       ├──► job_id 取得
       ├──► SSE or ポーリングで進捗監視
       └──► 完了時に video_id を取得
       │
       ▼
5. 生成された動画を textDB と紐付けて保存
   texts テーブルに generation_id, video_id を記録
       │
       ▼
6. フロントエンドで動画を表示
   GET /api/animation/{video_id}
```

### 6.4 コンテンツ追加フロー

- `.md` + インタラクティブコンポーネント形式でコンテンツを逐次 add
- セクション分割により動的にコンテンツが成長
- 各セクションに対応する動画を RAG 検索で再利用可能
  - `POST /api/search_animation` で類似コンテンツの既存動画を検索
  - 再生成せずに既存動画を引用する選択肢

       │
       ▼

       │
